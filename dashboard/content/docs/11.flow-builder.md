# Flow Builder

Build scripted IVR phone trees visually — no code, no AI, zero API cost. Drag and drop nodes on a canvas, connect them with edges, and save. FlowBrain executes the flow deterministically at runtime.

## Getting Started

1. Go to **Assistants** → click **New**
2. Set brain to **flow**
3. Open the **Flow** tab — you'll see the visual canvas with a **Call Start** trigger node
4. Add nodes from the toolbar, connect them by dragging handles
5. Click **Save** to write `flow.json`

## Node Types

### Trigger (Call Start)
The entry point of every flow. Automatically created. Cannot be deleted. Shows all built-in variables available at call start.

### Message
Plays an audio file or speaks TTS text, then automatically advances to the next connected node.

- **Audio**: Select a pre-recorded sound file from your assets
- **Text**: TTS fallback — spoken if no audio file is set
- **Next**: The node to transition to after playing

### Menu
Plays a prompt, then waits for the caller to press a DTMF key. Each key routes to a different node.

- **Options**: Each DTMF key (1, 2, 3...) connects to a target node via right-side handles
- **Timeout**: How long to wait for input (default: 10 seconds)
- **Retries**: How many times to replay the prompt on no input or invalid key (default: 3)
- **Next**: General fallback connection (bottom handle)

### Collect (Voice Input)
Plays a prompt, then listens for the caller to speak. The transcription is stored in a variable.

- **Audio/Text**: The prompt to play before listening
- **Variable**: The name to store the speech under (e.g., `name`, `reason`)

::callout{type="info"}
The transcription system runs continuously during the call. The Collect node simply switches the state to "listening" so incoming speech is captured and stored.
::

### Condition (IF)
Evaluates a variable and branches the flow in two directions: **TRUE** or **FALSE**.

- **Var**: Which variable to check (autocomplete shows available upstream variables)
- **Operator**: How to compare — equals, not equals, contains, not empty, empty, greater than, less than
- **Value**: The value to compare against (supports `{{variable}}` references)

### Transfer
Transfers the call to an extension or ring group. Terminal node — no outgoing connection.

- **Extension**: The destination (e.g., `200`, `ring-group-1`)

### Hangup
Optionally plays a goodbye message, then ends the call. Terminal node.

- **Audio/Text**: Optional farewell message

### Set Variable
Assigns a value to a variable. Useful for setting flags, building strings, or preparing data for conditions.

- **Name**: Variable name (e.g., `status`)
- **Value**: The value to assign — supports `{{variable}}` interpolation (e.g., `Hello {{name}}`)

### HTTP Request
Calls an external API and stores the response in a variable. Has two output paths: **next** (success) and **error** (failure/timeout/4xx/5xx).

- **Method**: GET, POST, PUT, or DELETE
- **URL**: The endpoint — supports `{{variable}}` interpolation
- **Store**: Variable name for the response body
- **Headers**: JSON string for custom headers
- **Body**: JSON string for request body (non-GET only)
- **Error path**: Connect the red "error" output to handle failures gracefully (e.g., play an apology message)

::callout{type="warning"}
HTTP requests have a 10-second timeout. The response is truncated to 2000 characters. If no error path is connected, errors are silently ignored and the flow continues to the "next" output.
::

## Variables

Variables are string values stored in memory during a call. Reference them anywhere with `{{variableName}}` syntax.

### Built-in Variables

| Variable | Description |
|----------|-------------|
| `{{caller}}` | Caller ID number |
| `{{extension}}` | Dialed extension |
| `{{date}}` | Current date |
| `{{time}}` | Current time (HH:MM) |
| `{{timestamp}}` | Full ISO timestamp |
| `{{digit}}` | Last DTMF key pressed |

### User Variables

Created by **Collect**, **Set Variable**, and **HTTP Request** nodes. The variable picker in the UI only shows variables that are reachable from upstream nodes in the current flow path — you won't accidentally reference a variable from a different branch.

### Interpolation

Use `{{variableName}}` in any text field:
- TTS text: `"Hello {{name}}, your appointment is on {{date}}"`
- HTTP URL: `"https://api.example.com/check?phone={{caller}}"`
- Set Variable value: `"Status: {{api_result}}"`
- Condition compare value: `"{{other_var}}"`

## Audio Files

Each Message, Menu, Collect, and Hangup node can play a pre-recorded audio file. The audio picker shows files from your **Assets** page (`custom/` folder).

- If an audio file is set, it plays first
- If no audio file is set (or playback fails), the TTS text is used as fallback
- If neither is set, the node is silent

Upload audio files on the **Assets** page. Recommended format: `sln16` (signed linear 16-bit, 16kHz).

## Saving & Loading

- **Save** writes the canvas to `assistants/<slug>/flow.json`
- **Load** reads `flow.json` and reconstructs the canvas on page load
- The flow is validated on save — all node types must be recognized
- Canvas positions are preserved in the JSON (`position: { x, y }`)

### Validation on Save

When you save, the builder checks for common issues and shows warnings:

- **Unreachable nodes** — nodes with no incoming connections
- **Dead-end nodes** — non-terminal nodes (not Transfer/Hangup) with no outgoing connections
- **Missing fields** — Transfer with no extension, Menu with no options, Collect with no variable, HTTP with no URL, Message with no audio or text, Condition with no variable
- **Disconnected menu options** — Menu nodes where none of the DTMF options are connected
- **Disconnected trigger** — Trigger node not connected to any node

Warnings don't block saving — the flow is saved regardless, but you should fix them before going live.

### Deleting Nodes

Press **Delete** to remove a selected node. If the node has connections, a confirmation dialog appears first — this prevents accidentally breaking your flow.

## Runtime Behavior

When a call comes in to a flow assistant:

1. FlowBrain loads `flow.json` and sets built-in variables
2. Execution starts at the trigger node and follows edges
3. **Message** nodes play audio/TTS and auto-advance
4. **Menu** nodes wait for DTMF — invalid keys or timeouts replay the prompt
5. **Collect** nodes wait for speech — the first transcription is captured
6. **Condition** nodes evaluate instantly and branch
7. **Transfer/Hangup** nodes end the flow

The flow is fully deterministic — same inputs always produce the same path. No AI model calls, no latency, no cost per call.
